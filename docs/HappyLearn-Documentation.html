1. Vision produit

Happy Learn transforme une séance scolaire en mission narrative : l’élève choisit un univers (football, rugby, équitation, espace), répond en mode cahier ou QCM, et gagne une récompense visuelle sans note ni classement.

  • Pour l’élève : engagement, feedback immédiat, aventure guidée par la mascotte Néo.
  • Pour l’enseignant : classes, liste d’élèves, pilotage de session live, stats non classantes, création de missions.
  • Pour l’école : application web (aucun install), code de session éphémère, traces pédagogiques.
État actuel : le catalogue affiche tous les niveaux (CP–CM2) et matières du primaire, mais seul le parcours CM2 mathématiques / fractions est jouable de bout en bout. Le créateur de missions permet déjà d’ajouter d’autres contenus multi-matières publiables dans le pilotage.

2. Ce qui a été livré

2.1 Socle application

  • SPA Vite + React 19 + TypeScript strict + React Router 7
  • Double backend : Supabase (Auth, Postgres, Realtime) ou fallback localStorage
  • Déploiement Cloudflare Pages (happy-learn.pages.dev)
  • Accessibilité : lecture à voix haute, lang=fr, aria-live, reduced-motion

2.2 Parcours élève (solo)

  • Connexion prénom (libre) ou via code de classe / session
  • Choix niveau + matière, présentation, univers, matériel (cahier/QCM), mission, récompense
  • Moteur unique de validation (fractions, nombres, texte, choix, bilan, teaser…)
  • 4 univers narratifs + scènes animées + collection de récompenses

2.3 Espace professeur

  • Auth e-mail / mot de passe (ou lien magique) ; mode local sans mot de passe
  • Multi-classes, roster élèves (prénom + nom), code classe
  • Stats filtrables (élève, session, dates) sans notes ni classement
  • Journal des séances

2.4 Sessions de classe live

  • Session éphémère avec code à 6 caractères
  • Salle d’attente élève, verrouillage de navigation
  • Présence roster (connecté / déconnecté / pas encore connecté)
  • Lancement / arrêt d’activité (mission + mode) ; univers choisi par l’élève
  • Kick / reconnexion, retour salle d’attente à l’arrêt d’activité

2.5 Catalogue & créateur de missions

  • Contrat d’IDs multi-matières : {niveau}-{matière}-{slug}-{nn}
  • Étapes canoniques : {missionId}/{slug} (ex. cm2-maths-fractions-01/s01)
  • Missions officielles en TypeScript + table Supabase missions (jsonb)
  • Éditeur in-app : création, duplication, preview, publication

6. Modèle de données & contrat missions

6.1 Tables Supabase (principales)

  • classes, profils_enseignants, eleves_classe
  • classe_sessions, session_participants
  • sessions_enfant, reponses, collection
  • missions (document JSON d’étapes, source = builtin | teacher)
  • etapes : legacy seed, dépréciée pour le runtime

6.2 Identifiants standardisés

Mission : cm2-maths-fractions-01

Étape : cm2-maths-fractions-01/s01

Règles détaillées : src/data/missions/CONTRACT.md

Les scènes visuelles utilisent une clé scene (souvent l’ancien id court T00, M01…) pour ne pas casser les animations tout en stockant des ids canoniques dans les réponses / analytics.

7. Sécurité, déploiement & exploitation

  • Auth élèves : pas de compte e-mail ; prénom libre ou sélection roster.
  • Auth enseignants : Supabase Auth (self-signup ouvert en démo).
  • RLS : encore permissives sur certaines écritures (traces) — à resserrer.
  • Secrets : variables VITE_* / VITE_HL_* au build ; token migrations hors dépôt.
  • Déploiement : npm run build puis Cloudflare Pages / Wrangler.

8. Limites du MVP

  1. Un seul parcours officiel jouable (CM2 maths fractions).
  2. Sessions live dégradées hors Supabase (mono-appareil localStorage).
  3. RLS / anonymat trop ouverts pour une production scolaire stricte.
  4. Pas d’export de données, pas de multi-établissements, pas de SSO ENT.
  5. Créateur : pas d’édition des animations UniverseScene par étape.
  6. Kinds avancés (matching, ordonnancement…) non exposés.
  7. Pas de suite de tests automatisés complète des 8 parcours checklist.
  8. Pas de gestion fine des rôles (directeur, formateur, éditeur pédagogique).

9. Axes d’amélioration & feuille de route « produit pro »

Priorisation proposée par impact pédagogique / risque / effort technique. Pas d’estimation calendaire : chaque axe liste les chantiers concrets.

9.1 Fondations production (priorité haute)

ChantierPourquoiLivrables
Durcir la sécurité (RLS, auth) Données mineurs, conformité école Politiques par rôle ; join session signé ; rate-limit ; audit logs
Observabilité Déboguer en classe réelle Sentry / logs structurés ; métriques sessions live ; alertes Realtime
Environnements Éviter de casser la démo staging + prod ; migrations versionnées CI ; feature flags
Qualité Régressions parcours Tests e2e (élève solo, live, créateur) ; checklist PARCOURS-8 automatisée

9.2 Contenu pédagogique (priorité haute)

  • Publier 3–5 missions officielles par matière prioritaire (maths, français) sur CE1–CM2.
  • Bibliothèque de kinds multi-matières : texte, QCM, appariement, ordre, dictée courte.
  • Validation éditoriale (brouillon → revue → publié) avec versioning.
  • Packs de mission « séance 45 min » alignés programmes.

9.3 Expérience enseignant (priorité haute / moyenne)

  • Tableau de bord séance : progression live par élève (étape courante, aides utilisées).
  • Export CSV / PDF des traces (répondances, temps, univers) pour le cahier journal.
  • Modèles de session (niveau + matière + mission + mode mémorisés).
  • Gestion d’année scolaire, archivage, import roster (CSV / Pronote / ENT).

9.4 Expérience élève (priorité moyenne)

  • Accessibilité renforcée (contrastes, dys, taille texte, clavier complet).
  • Mode « reprise » si coupure réseau / changement d’appareil.
  • Différenciation : variantes d’étapes selon profil (aide renforcée).
  • Récompenses & collection enrichies sans gamification toxique (toujours sans classement).

9.5 Créateur de missions (priorité moyenne)

  • Textes par univers (au-delà du mode « 1 texte → 4 univers »).
  • Éditeur de scène / assets, preview joueur fidèle (iframe player).
  • Import / export JSON, duplication inter-classes, co-édition.
  • Banque d’items partagée (établissement / académie).

9.6 Offre & distribution (priorité moyenne / basse)

  • Domaine custom, branding école / éditeur.
  • Comptes établissement, licences, facturation.
  • SSO ENT / GAR, RGPD (DPA, consentements parentaux si besoin, droit à l’oubli).
  • Application tablette offline-first (PWA cache missions).

9.7 Roadmap synthétique

VagueObjectifRésultat attendu
Vague A Socle pro Sécurité + CI + e2e + staging Déploiement fiable en classe pilote
Vague B Contenu Catalogue multi-matières réel Plusieurs séances prêtes à l’emploi
Vague C Pilotage Live + exports + dashboard Usage quotidien enseignant
Vague D Échelle Établissements, ENT, licences Produit commercialisable
Recommandation : avant d’élargir massivement le contenu, sécuriser RLS / auth et industrialiser les tests e2e des parcours live. Ensuite, enchaîner contenu officiel + exports enseignant — ce sont les deux leviers qui transforment la démo en outil de classe.
